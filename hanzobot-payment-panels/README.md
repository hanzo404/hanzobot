# هانزبات: پنل‌های پرداخت (چند فروشنده / چند قیمت)

افزونه‌ی ووکامرس برای پیاده‌سازی همان الگوی **تکنولایف**: روی صفحه‌ی محصول، کنار «قیمت اصلی»، چند پنل/فروشنده‌ی دیگر با قیمت متفاوت نمایش داده می‌شود؛ هر پنل به یک **درگاه پرداخت** وصل است و قیمتش با یک **درصد دلخواه** (مثلاً ۱۳٪ برای اسنپ‌پی و ترب‌پی) محاسبه می‌شود. هنگام تسویه‌حساب، درگاه پرداخت مشتری به همان پنل **قفل** می‌شود و پنل انتخابی در سبد، سفارش، ایمیل و پیشخوان ثبت می‌گردد.

مثال (قیمت پایه ۱٬۲۵۰٬۰۰۰ تومان با رُند به بالا):

| پنل | درصد | قیمت مشتری | اقساط |
|---|---|---|---|
| فروشنده‌ی اصلی — پرداخت آنلاین | ۰٪ | ۱٬۲۵۰٬۰۰۰ | — |
| درگاه پرداخت اسنپ‌پی | +۱۳٪ | ۱٬۴۱۳٬۰۰۰ | ۴ × ۳۵۳٬۰۰۰ |
| درگاه پرداخت ترب‌پی | +۱۳٪ | ۱٬۴۱۳٬۰۰۰ | ۴ × ۳۵۳٬۰۰۰ |

> پیش‌نمایش زنده‌ی ظاهر و منطق افزونه: فایل `demo/index.html` در همین مخزن.

---

## چطور کار می‌کند (جریان خرید)

1. مشتری روی صفحه‌ی محصول، پنل مورد نظرش را می‌بیند (قیمت هر پنل همان‌جا نمایش داده می‌شود).
2. با کلیک روی دکمه‌ی همان پنل، محصول **با همان قیمت** به سبد اضافه می‌شود (پارامتر `hanzobot_plan` همراه درخواست می‌رود).
3. قیمت قلم سبد با فیلتر رسمی ووکامرس (`woocommerce_before_calculate_totals`) روی قیمت پنل قفل می‌شود؛ پس با تغییرات بعدی قیمت محصول یا محاسبه‌ی چندباره‌ی مجموع، قیمت جابه‌جا نمی‌شود.
4. در تسویه‌حساب فقط درگاهِ همان پنل باز می‌ماند (فیلتر `woocommerce_available_payment_gateways`) و اگر کاربر درگاه دیگری را انتخاب کند، خطا می‌گیرد.
5. پنل و درصد روی قلم سفارش (`پنل پرداخت`)، متای سفارش (`_hzmp_plan`) و یک یادداشت داخلی سفارش ثبت می‌شود.

برای محصولات **متغیر** (مثل محصولات سایت ینولایف)، قیمت پنل‌ها با انتخاب رنگ/مدل به‌صورت زنده به‌روز می‌شود و تا وقتی متغیر انتخاب نشده، دکمه‌های خرید غیرفعال‌اند و پیام «ابتدا گزینه را انتخاب کنید» نمایش داده می‌شود.

---

## نصب

1. پوشه‌ی `hanzobot-payment-panels` را ZIP کنید (یا از فایل ZIP آماده‌ی `hanzobot-payment-panels.zip` استفاده کنید).
2. پیشخوان وردپرس → **افزونه‌ها ← افزودن ← بارگذاری افزونه** → نصب و فعال‌سازی.

نیازمندی: ووکامرس فعال + PHP 7.0 و بالاتر.

پس از فعال‌سازی: **ووکامرس ← پنل‌های پرداخت**.

## تنظیمات (کوتاه و کاربردی)

### ۱) عمومی
| گزینه | توضیح |
|---|---|
| محل نمایش | پیش‌فرض: بعد از دکمه‌ی افزودن به سبد. برای قالب‌هایی با باکس خرید سفارشی، شورت‌کد `[hanzobot_panels id="۱۲۳"]` را هر جا لازم است بگذارید. |
| افزودن آجاکسی | سبد و مینی‌کارت قالب بدون رفرش به‌روز می‌شود (در صورت خطا، خودکار به ارسال معمولی برمی‌گردد). |
| مخفی کردن دکمه‌ی قالب | اگر می‌خواهید خرید **فقط** از پنل‌ها انجام شود. سلکتور دکمه‌ی قالب قابل تغییر است. |
| رُند کردن قیمت | پیش‌فرض: رُند به بالا تا نزدیک‌ترین ۱٬۰۰۰ تومان (یعنی فروشگاه هیچ‌وقت ضرر نمی‌کند). |
| قفل درگاه پرداخت | با انتخاب هر پنل، فقط درگاه همان پنل باز می‌ماند. |
| پنل اقلام بدون انتخاب | پیش‌فرض: «پنل پایه»؛ یعنی محصولی که از صفحه‌ی فروشگاه یا با پارامتر آدرس اضافه شود، با قیمت اصلی حساب می‌شود و درگاه‌های اقساطی برایش باز نمی‌شود (جلوگیری از ضرر کارمزد). |
| به‌خاطر سپردن پنل | اگر قالب یا افزونه‌ای پارامتر پنل را در درخواست آجاکسی حذف کند، انتخاب مشتری با یک کوکی کوتاه‌عمر (پیش‌فرض ۴۵ دقیقه، فقط برای همان محصول) یادآوری می‌شود. |
| سبد با پنل‌های متفاوت | پیام توضیحی (پیش‌فرض) یا جلوگیری از پرداخت. |

### ۲) پنل پایه و ۳) پنل‌های دیگر
برای هر پنل: عنوان، زیرعنوان، **درصد**، **شناسه‌ی درگاه**، تعداد اقساط + متن اقساط، بج و رنگ و آیکن، مزیت‌ها (هر خط یک تیک) و متن دکمه.

**پیدا کردن شناسه‌ی درگاه:** در همان صفحه، همه‌ی درگاه‌های ثبت‌شده‌ی ووکامرس با شناسه (`id`) و وضعیت فعال/غیرفعال لیست می‌شوند؛ کافی است تیک بزنید. اگر فیلد خالی بماند، افزونه با کلیدواژه‌ها (`snapp`, `torobpay`, ...) خودش تشخیص می‌دهد و در جعبه‌ی «وضعیت» بالای صفحه گزارش می‌دهد.

**درصد محصول‌به‌محصول:** در صفحه‌ی ویرایش هر محصول، متاباکس «پنل‌های پرداخت» اجازه می‌دهد پنل را برای آن محصول خاموش کنید یا درصد اختصاصی بدهید (خالی = پیش‌فرض افزونه).

## نکته‌ی مهم: حالت «تخفیف پرداخت نقدی» (توصیه‌شده)

قرارداد درگاه‌های اقساطی (ترب‌پی/اسنپ‌پی) معمولاً اجازه نمی‌دهد **قیمت بالاتری به مشتری قسطی** بفروشید؛ یعنی «گران‌تر شدن محصول به‌خاطر درگاه» از نظر پلتفرم محل اشکال است. راه ایمن و مرسوم این است که برعکسش را انجام دهید:

- **قیمت محصول** را همان قیمت درگاه‌های اقساطی بگذارید (همان عددی که به ترب/اسنپ اعلام می‌کنید).
- **پنل پایه («پرداخت نقدی/آنلاین») را با درصد منفی** تعریف کنید؛ یعنی به مشتری نقدی **تخفیف پرداخت نقدی** بدهید.

تبدیل درصد (ریاضی ساده):

```
درصد تخفیف نقدی = درصد افزایش ÷ (۱ + درصد افزایش)
۱۳٪ ÷ ۱٫۱۳ ≈ ۱۱٫۵٪  ⇒  پنل پایه: -11.5
```

با این تنظیم، پنل پایه مثلاً ۱۱٫۵٪ ارزان‌تر از دو پنل دیگر نمایش داده می‌شود، قیمت اعلامی به ترب/اسنپ دست‌نخورده می‌ماند و منطق قفل درگاه هم همان‌طور کار می‌کند.

## سازگاری

- **وودمارت و قالب‌های آجاکسی:** دکمه‌های پنل، دکمه‌ی خود قالب نیستند؛ درخواست افزودن به سبد را افزونه با `wc-ajax=add_to_cart` می‌فرستد (پارامتر `add-to-cart` عمداً حذف می‌شود تا هسته‌ی ووکامرس محصول را دوبار اضافه نکند) و رویداد استاندارد `added_to_cart` را هم صدا می‌زند تا مینی‌کارت قالب به‌روز شود.
- **افزونه‌ی «ورود اجباری برای افزودن به سبد» (همین مخزن):** برای مهمان‌ها، افزونه‌ی ما مسیر آجاکسی جداگانه باز نمی‌کند؛ دکمه‌ها کلاس `hzmp-add-to-cart` دارند و فرم هر پنل فیلدهای `add-to-cart`/`variation_id`/`hanzobot_plan` را دارد، پس افزونه‌ی ورود اجباری همان جریان «افزودن به سبد مهمان ← هدایت به ورود ← برگشت» را با حفظ پنل انجام می‌دهد.
- **بلوک‌های ووکامرس (Checkout/Cart Block):** پشتیبانی می‌شود؛ قیمت‌ها از سبد محاسبه می‌شوند، پنل در متای اقلام سفارش ثبت می‌گردد و **قفل درگاه هم سمت سرور اعمال می‌شود** (Store API فهرست درگاه‌های مجاز را از `get_available_payment_gateways()` می‌گیرد و درگاه غیرمجاز را رد می‌کند). قاعده‌ی «سبد با پنل‌های متفاوت» در مسیر بلاکی با `woocommerce_store_api_cart_errors` اجرا می‌شود.
- **HPOS (جداول جدید سفارش):** سازگاری اعلام شده است.
- **کش:** خروجی پنل‌ها کش‌پذیر است (هیچ nonce یا مقدار سشنی در HTML نیست). اگر کش صفحه، پارامتر درخواست آجاکسی را حذف کند، کوکی یادآوری پنل جلوی افت قیمت را می‌گیرد.

## عیب‌یابی

| نشانه | راه‌حل |
|---|---|
| پنل‌ها نمایش داده نمی‌شوند | در جعبه‌ی «وضعیت» ببینید درگاه پنل‌ها شناسایی شده و «فعال» است؛ با گزینه‌ی پیش‌فرض، پنلی که درگاهش فعال نباشد پنهان می‌شود. |
| قیمت پنل اضافه نشد | مطمئن شوید درگاه‌ها به پنل درست متصل‌اند و پارامتر `hanzobot_plan` در درخواست هست (در حالت قالب‌های سفارشی، گزینه‌ی «به‌خاطر سپردن پنل» را روشن بگذارید). |
| مشتری با درگاه دیگری پرداخت می‌کند | «قفل درگاه پرداخت» باید روشن باشد؛ اگر افزونه‌ی درگاه با نام دیگری، درگاه را پس از محاسبه‌ی مجموع اضافه می‌کند، شناسه‌ی همان درگاه را در پنل تیک بزنید. |
| دکمه‌ی خرید غیرفعال است | محصول متغیر است و رنگ/مدل انتخاب نشده، یا محصول ناموجود است. |

## قلاب‌ها برای توسعه‌دهنده

```php
// تغییر تنظیمات در زمان اجرا
add_filter( 'hzmp_settings', function ( $s ) { return $s; } );

// قیمت نهایی قلم سبد
add_filter( 'hzmp_cart_item_price', function ( $price, $item, $cart ) { return $price; }, 10, 3 );

// درگاه‌های یک پنل (مثلاً اتصال به درگاه دلخواه)
add_filter( 'hzmp_plan_gateways', function ( $ids, $plan ) {
	return ( 'p1' === $plan ) ? array( 'my_snapp_gateway' ) : $ids;
}, 10, 2 );

// درصد اختصاصی (به‌جای متاباکس، از روی داده‌های خودتان)
add_filter( 'hzmp_panel_pct', function ( $pct, $plan, $product_id ) { return $pct; }, 10, 3 );

// پنل حاکم بر سبد
add_filter( 'hzmp_cart_plan', function ( $plan, $cart ) { return $plan; }, 10, 2 );

// نمایش/عدم نمایش پنل‌ها برای یک محصول خاص
add_filter( 'hzmp_show_panels', function ( $show, $product, $cards ) { return $show; }, 10, 3 );
```

توابع کمکی: `hzmp_get_cards( $product_id )` (داده‌ی همه‌ی پنل‌ها با قیمت محاسبه‌شده) و `hzmp_cart_plan()` (پنل حاکم بر سبد).
